### skills/rug-check/SKILL.md (Skill: Rug check, file)

```md
# Rug check

## When to use
Before any buy proposal on a token, and whenever I ask if a token is safe or a rug.

## Inputs
Token address, the chain, and the deployer wallet if I have it. If the address is missing, ask once and stop.

## Steps
1. Check mint control: mint and freeze authority renounced, or no owner who can mint or pause. Pass only then.
2. Check liquidity: pass only if the LP is locked or burned and the deployer does not hold it.
3. Check holders: pass only if the top 10 wallets, LP excluded, hold under 30%.
4. Look up the deployer's past tokens and how each one ended.
5. Check whether the socials look real or bought: account age, follower overlap, repeated replies.
6. Write one line per check, then the verdict: CLEARED only if the first three pass and the deployer has no prior rug, else RUG RISK with the failed check named.

## Validate
Every check line has a number, address or link I can look up. A check you could not run counts as a fail. CLEARED never means buy; it only lets you propose one.

## Returns
Five lines, one per check, then one verdict line: CLEARED or RUG RISK. Sent to me in this chat.

## Requires approval
none
```

# Position log

3. If the size is over my per-trade cap, say so in the first line.
4. If my last closed entry was a loss and this size is larger, say "size up after a loss" in the first line.
5. On "I'm out", add the exit price, exit size and the result as a percent of entry to that entry.
6. On "where am I", read back every open entry, newest first, with its kill line.
7. Record only: logging never places, changes or closes a trade. Never delete or overwrite an entry; fix a mistake with a new line marked CORRECTION.

## Validate
Each entry has token, entry price, size, thesis and kill line, or the gap is marked MISSING. No entry was deleted or overwritten.

## Returns
On a log: one confirmation line plus any flag. On where am I: one line per open entry with token, entry, size and kill line.

## Requires approval
none

# Edge-gone exit

## When to use
When my kill line breaks, when I ask whether to get out, or when a logged thesis stops being true.

## Inputs
The open entry from the position log, the current price, and fresh holder and liquidity data.

## Steps
1. Read the entry from the position log. If there is no entry for the token, say so and stop.
2. Test the thesis against today. Name which one broke: the kill line, the theme (now tired), or a rug check.
3. Re-run rug-check on the token. Mint control regained, LP pulled or a top-10 dump is an EXIT.
4. If nothing broke, say HOLD and restate the kill line. Do not invent a reason to exit.
5. If something broke, write the proposal: EXIT or TRIM, size, current price and the broken condition.
6. Never propose adding size to a losing position in place of an exit.
7. Put the proposal to me and wait for my yes at the trade gate. With no yes, take no trade action.
8. After I confirm a sell is done, add the exit to the position log.

## Validate
The broken condition is cited with a number, level or link. A hunch is not a reason to exit.

## Returns
Verdict first: EXIT, TRIM or HOLD. Then the broken condition, size, current price and kill line. Sent to me in this chat.

## Requires approval
trade: ask at the trade gate before any sell, swap or close. Without a yes, propose only.
